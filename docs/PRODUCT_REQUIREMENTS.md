# 商用产品要求与编辑验收

2026-09-25 用户反馈，后续版本持续遵守：

1. 面向用户的应用是完整产品，不展示开发修改过程。只显示当前菜谱总量与分类数量；不显示“新增66道”“新”标签、“验收版”等。版本历史留在发布说明和内部记录。
2. 步骤面向第一次做这道菜的人。不能把洗切、调汁、预热、下料、翻面、熟透判断挤进四五个大步骤。按独立操作与判断点拆分，不能为了凑步骤数拆成空话。
3. 交付目标为可申请应用市场上架的商用版本。去掉开发字样不等于达到商用质量；来源、试做、手机验收等实际状态必须如实记录。

## 每道菜的编辑规则

- 开火前：称量，解冻/浸泡/腌制等前置条件，洗切尺寸，调料分装，锅具和容器尺寸。
- 开火后：每一步明确先后顺序、放什么和多少、火力、是否盖盖、持续多久、何时翻面/翻炒。
- 时间必须带状态判断。说明何时开始计时、到时检查哪里、未达到状态如何继续；不把计时当熟透保证。
- 分次使用的油、盐和水从同一份材料清单扣分量，不重复加入总量。份量改变时联动；厚度、温度、单锅时间不直接倍乘。
- 焯水和清洗用水与实际入菜液体分开说明；主料、调料均有明确去向。
- 至少针对本菜解释容易失败的操作与补救，避免泛泛的“注意火候”“炒至熟”。
- 简单菜可以少于八步，复杂菜可以超过十二步；质量依据可操作性，不依据步数。
- 文字编辑完成、来源支持、厨房试做、真机验收分别记录。自动检查只发现结构问题，不能证明菜好吃或做法已验证。

## 本轮执行顺序

用户在同日后续语音中明确调整优先级：先做整体产品、菜系覆盖与难度筛选；旧菜步骤的全面细化留在后面。按“菜系扩充 → 来源与厨房验证 → 产品功能与上架准备”的阶段路线推进，并在最终内容验收前完成步骤细化。现已做好的红烧肉与香蕉厚蛋烧细化保留，不继续让全库重写阻塞框架交付。

难度按具体菜的刀工、火候、成形、多工序等操作判断，不把川菜整体归为简单、鲁菜整体归为困难。提供“轻松做、日常做、挑战做”和全部难度入口，可与菜系、用时、忌口同时筛选。菜系显示顺序优先川、湘；“山东菜”和“鲁菜”合并，搜索可使用地区别名。

发布前统一打包，保留旧用户收藏；不让用户为每处文案修改反复下载安装。
