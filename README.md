# 今天吃什么

一个为家庭厨房做的离线 Android 应用：随机选一道家常菜或早餐，按人数准备材料，照步骤做饭。

**当前为 v0.5.0 阶段验收版。适用于 Android 8.0+，面向荣耀 Magic6 / 荣耀400 的 MagicOS。用户已体验第四版并提出反馈；第五版尚待用户真机验收。不包含 HarmonyOS NEXT 原生安装包，尚未达到商业上架验收标准。**

[下载新版 APK](https://github.com/leijiangjiang547-arch/jintian-chi-shenme/releases/download/v0.5.0/cookdaily-v0.5.0.apk) · [本次发布](https://github.com/leijiangjiang547-arch/jintian-chi-shenme/releases/tag/v0.5.0) · [分阶段计划](docs/ROADMAP.md)

## 手机安装

1. 在手机浏览器打开本仓库，进入 **Releases（发布）**。
2. 下载 `cookdaily-v0.5.0.apk`，不要下载 Source code 压缩包当作安装包。
3. 点击下载的 APK，按手机提示仅允许当前下载来源安装，然后安装。无需关闭全局安全保护。
4. 在桌面打开“今天吃什么”。全部180道文字菜谱与AI成品示意图已内置，首次打开也不依赖联网；外部教程需要网络。

已经安装旧版时，直接覆盖安装，保留本机收藏和清单。新版使用相同包名和签名，版本号递增；不要先卸载旧版，否则本机数据会随卸载删除。

代码仓库中的 `downloads/` 也保存相同 APK，可进入该文件后点击 **Download raw file** 下载。

## 已实现

- 100道家常菜、80道早餐；固定内置数据，不调用大模型。其中6道家常快手菜预计10–15分钟（含两人份常规备料，未实做计时）。
- 增加香蕉厚蛋烧、蓝莓西多士、虾滑馄饨面、烧卖、饭团、蒸糕等；早餐中面条粉类为10道。
- 补入红烧肉、回锅肉、可乐鸡翅、清蒸鲈鱼、锅塌豆腐、天津独面筋等常见菜。
- 菜系、菜名/地区别名或食材搜索、最长用时、不吃辣、排除食材、菜品种类、不吃面条粉类。
- “轻松做、日常做、挑战做”操作难度，可与其他条件组合；一键重置筛选。难度与耗时独立。
- 八大菜系各有代表菜，另有津菜与东北风味；覆盖尚不全面。较复杂的本轮候选菜留在下一阶段，未放入本次应用。
- 应用界面不显示“新增”标记和修改记录；历史变化只在发布说明记录。
- 随机推荐避开最近10次结果，有候选时优先换一种菜品类型，再选具体菜；候选太少时逐级放宽。
- 1–6人份量换算：食材和调料换算，计时不倍增，多人份分批做。
- 收藏、购物清单、同名同单位食材合并，保存在本机。
- 原生 AlarmManager 单个步骤提醒、通知声音与振动；需用户开启通知与精确计时，未授权明确降级为前台提醒。系统时钟为备用入口。声音仍受音量、勿扰及厂商省电影响，强行停止/重启后需重新计时。
- 大按钮做菜、可选横屏、触控锁、下一步防重复点击；仅做菜模式保持屏幕常亮。
- JSON 文件导出/恢复、深色与跟随系统外观、最近做过记录，随机推荐尽量避开近7天做过的菜。
- 食材同义词、多关键词交集、菜名拼音首字母搜索；15分钟空结果显示实际最低用时，放宽时间时保留忌口。
- 买菜勾选仅在食材用量增加时需重新核对；减少用量时保留勾选。计数单位给取用提示；鸡蛋保留比例并提示蛋液克数。
- 醒目过敏原标签；180道离线AI成品示意图（非实拍），每道菜另附成品图片搜索入口，清楚提示联网、登录和广告可能性。
- 原文、相关技法和视频核查状态分别标示；外链通过系统浏览器打开。
- 无账号、无广告、无付费接口、无统计 SDK。

- 首页先筛选再抽选；修改条件只更新候选数，保留并标明上次抽选结果。
- 首页、菜谱、收藏共享筛选，包含不吃面条、搜索、菜系和种类，重启后保留。
- 步骤勾选与做菜模式进度按菜谱保存；菜谱步骤改变后旧进度失效，避免错位。
- 本机存储版本2，兼容第四版数据；JSON备份版本2包含进度，仍支持导入版本1。
- 全库分次用料改为显式引用，避免运行时用正则猜测油盐分配。

## 菜谱质量与来源

参考 [Anduin2017/HowToCook](https://github.com/Anduin2017/HowToCook) 的63份文档，固定到提交 `c2063eb7050bac0cb998779c62fa08c649c9882f`。详见 [来源审计](docs/source-audit.json) 和 [复用决策](docs/REUSE.md)。应用中的配方为家庭量化改编，**不是原菜谱的逐字复制，也不是所有视频的逐帧转录**。

上游部分配方的用量和操作不一致，已进行编辑修订，例如：蒸蛋按蛋液质量配水、分浅碗蒸并检查中心凝固；四季豆预煮并充分焖熟；剩饭明确冷藏要求；肉类增加中心温度检查。原文或相关技法链接保留，便于复核。

第二版来源见 [来源登记](docs/expansion-sources.json)，第三版来源与覆盖情况见 [内容审计](docs/v03-content-audit.json)。对应做法、相关技法、仅标题/简介和平台文字摘要的核查深度在菜谱旁标明。部分来源只支持技法，配料和用量经过家庭改编，不能视为原作者配方或认可。未将平台搜索入口标成已核验视频；未下载或重新分发平台视频、图片。

**180道菜尚未逐道试做。用量、火候、用时需要真实厨房验证，不能将程序测试通过当作味道或食品安全已获验证。** 过敏原标识只依据主要食材，复合调味品、半成品请核对完整标签。当前是阶段扩充，未宣称覆盖全部菜系。

## 重建 APK

使用官方 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。构建只调用 `aapt2`、`javac`、`R8`、`zipalign` 和 `apksigner`，无需 Gradle、Kotlin、Compose 或网络依赖。

先设置环境变量，再运行 `python scripts/build_apk.py`：

| 变量 | 内容 |
| --- | --- |
| `JAVA_HOME` | JDK 17 根目录 |
| `ANDROID_BUILD_TOOLS` | 包含 aapt2、zipalign、lib 的 Build Tools 35.0.0 目录 |
| `ANDROID_PLATFORM` | 包含 android.jar 的 android-35 目录 |
| `COOK_KEYSTORE` | 仓库外的持久签名文件路径；缺失时停止构建，避免误换升级证书 |
| `COOK_KEYSTORE_PASS` | 通过进程环境注入的签名密码，不写进源码 |
| `COOK_BUILD_DIR` | 可选，构建输出目录；默认 build/ |

成功后生成 APK 和 `SHA256SUMS.txt`。升级安装必须使用相同签名密钥；密钥不能提交到 GitHub。当前密钥保存在开发机的仓库外，密码通过 Windows DPAPI 加密，未包含在交付包中。

编辑菜谱可直接修改 `web/recipes.json` 并运行 `python scripts/sync_recipes.py`，再运行测试。编辑源在 `scripts/expand_catalog.py` 和 `scripts/expand_v03.py`；重新生成时按此顺序运行两者，再运行 `scripts/upgrade_v05.py`，最后应为180道（该脚本需要本地固定提交的HowToCook来源目录）。新增/更名后用 `pypinyin==0.55.0` 运行 `scripts/build_search_index.py` 更新首字母索引；拼音仅为构建时依赖，应用运行无依赖。对本批次的持久修订先改对应脚本，避免重建时覆盖。`make_recipes.py` 保留最初100道生成规则；不要单独运行它覆盖新版目录。

本轮23项核心测试、三组DOM检查、390px手机宽度与844×390横屏浏览器检查通过；尚未完成第五版安卓真机验证。手机逐项检查见 [第五版验收单](docs/ACCEPTANCE-v0.5.0.md)。先验证覆盖安装、飞行模式、后台计时权限/响铃、文件备份恢复、深色与横屏。再实做西红柿炒鸡蛋、葱花鸡蛋饼、香菇炒鸡片各一次，记录锅具、火力、实际用时、咸淡和难懂步骤。
