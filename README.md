# 今天吃什么

一个为家庭厨房做的离线 Android 应用：随机选一道家常菜或早餐，按人数准备材料，照步骤做饭。

**当前为 v0.1.0 个人验收版。适用于 Android 8.0+，包括荣耀 Magic6 / 荣耀400 的 MagicOS。未在这两款真机上完成实测；不包含 HarmonyOS NEXT 原生安装包。**

## 手机安装

1. 在手机浏览器打开本仓库，进入 **Releases（发布）**。
2. 下载 `cookdaily-v0.1.0.apk`，不要下载 Source code 压缩包当作安装包。
3. 点击下载的 APK，按手机提示仅允许当前下载来源安装，然后安装。无需关闭全局安全保护。
4. 在桌面打开“今天吃什么”。全部100道文字菜谱已内置，首次打开也不依赖联网；外部教程需要网络。

代码仓库中的 `downloads/` 也保存相同 APK，可进入该文件后点击 **Download raw file** 下载。

## 已实现

- 60道家常菜、40道早餐；固定内置数据，不调用大模型。
- 分类、菜名或食材搜索、最长用时、不吃辣、排除食材。
- 随机推荐避开最近10次结果；候选太少时仍尽量不连续重复。
- 1–6人份量换算：食材和调料换算，计时不倍增，多人份分批做。
- 收藏、购物清单、同名同单位食材合并，保存在本机。
- 大字分步做菜、熟透检查、勾选步骤、单个倒计时；后台不能保证及时响铃，回到前台按实际时间恢复。
- 原文、相关技法和视频核查状态分别标示；外链通过系统浏览器打开。
- 无账号、无广告、无付费接口、无统计 SDK。

## 菜谱质量与来源

参考 [Anduin2017/HowToCook](https://github.com/Anduin2017/HowToCook) 的63份文档，固定到提交 `c2063eb7050bac0cb998779c62fa08c649c9882f`。详见 [来源审计](docs/source-audit.json) 和 [复用决策](docs/REUSE.md)。应用中的配方为家庭量化改编，**不是原菜谱的逐字复制，也不是所有视频的逐帧转录**。

上游部分配方的用量和操作不一致，已进行编辑修订，例如：蒸蛋按蛋液质量配水、分浅碗蒸并检查中心凝固；四季豆预煮并充分焖熟；剩饭明确冷藏要求；肉类增加中心温度检查。原文或相关技法链接保留，便于复核。

目前有5个具体视频链接（涉及4道菜），核查深度已在各链接旁标明；其余菜谱提供图文参考和明确标注的平台搜索入口。未把平台搜索入口标成“已核验视频”。视频及平台图片没有被下载或重新分发。

**100道菜尚未逐道试做。用量、火候、用时需要真实厨房验证，不能将程序测试通过当作味道或食品安全已获验证。** 过敏原标识只依据主要食材，复合调味品、半成品请核对完整标签。

## 本地预览和测试

需要 Node.js 18+、Python 3.10+，运行时没有 npm 依赖。

```powershell
npm test
npm run preview
```

打开 `http://127.0.0.1:8765`。网页预览与 APK 共用同一套页面和数据；网页运行不等于 Android 真机验证。

## 重建 APK

使用官方 JDK 17、Android SDK Platform 35、Build Tools 35.0.0。构建只调用 `aapt2`、`javac`、`D8`、`zipalign` 和 `apksigner`，无需 Gradle、Kotlin、Compose 或网络依赖。

先设置环境变量，再运行 `python scripts/build_apk.py`：

| 变量 | 内容 |
| --- | --- |
| `JAVA_HOME` | JDK 17 根目录 |
| `ANDROID_BUILD_TOOLS` | 包含 aapt2、zipalign、lib 的 Build Tools 35.0.0 目录 |
| `ANDROID_PLATFORM` | 包含 android.jar 的 android-35 目录 |
| `COOK_KEYSTORE` | 仓库外的持久签名文件路径；不存在时自动生成 |
| `COOK_KEYSTORE_PASS` | 通过进程环境注入的签名密码，不写进源码 |
| `COOK_BUILD_DIR` | 可选，构建输出目录；默认 build/ |

成功后生成 APK 和 `SHA256SUMS.txt`。升级安装必须使用相同签名密钥；密钥不能提交到 GitHub。当前密钥保存在开发机的仓库外，密码通过 Windows DPAPI 加密，未包含在交付包中。

编辑菜谱可直接修改 `web/recipes.json` 并运行 `python scripts/sync_recipes.py`，再运行测试。`make_recipes.py` 保留最初生成规则；它需在本仓库两级目录外的 `work/HowToCook` 存放固定版本的上游 checkout。

## 验收建议

先验证手机安装、飞行模式启动、随机抽菜、收藏重开、份量换算、计时与返回键。再实做西红柿炒鸡蛋、葱花鸡蛋饼、香菇炒鸡片各一次，记录锅具、火力、实际用时、咸淡和难懂步骤。

应用市场上架、收费、广告、支付和商业化均未执行。后续以真机与厨房验收结果决定是否投入。
